# 安全边界

本文件记录安全边界，不代表实验版已经满足全部要求。当前定位为可信局域网内的自用小工具：保留 LocalSubnet，自用不要求签名，独立 SSH 撤销暂不优先。0.2.0 已有只读检查界面、配置确认、短期授权复用、就绪检查与清理反馈；系统级双机验收和剩余差距见 `开发交接.md`。后续若正式分发，再补齐可恢复撤销、审计和发布可信验证。

## 必须满足

- 所有连接必须由目标机用户明确启动，或由已登记的系统服务按策略启动。
- SSH 配对使用短期管理端 Ed25519 公钥，目标用户首次明确允许；同一公钥、来源 IP 和实例在原期限内复用，变化时重新确认。私钥保存在管理端当前用户 ACL 独占的短期缓存，不续期。
- Relay 只转发加密数据，不默认保存终端内容。
- 会话令牌短期有效，可立即撤销。
- 防火墙规则限制来源地址或仅允许本机隧道。
- 安装器提供卸载和回滚。
- 自用构建不要求签名；后续正式发布前进行签名校验。

## 明确禁止

- 在程序中硬编码管理员密码。
- 默认开放 0.0.0.0:22、2222、5985 或 3389 到公网。
- 通过隐藏窗口、计划任务或注册表实现未告知的持久化。
- 绕过 UAC、屏幕录制授权或用户确认。
- 将目标机文件和命令输出上传到未授权的第三方服务。

## 风险处理

- 临时账号：设置过期时间，结束会话时删除。
- 管理端丢失：通过 Relay 控制台立即撤销设备。
- Relay 泄露：设备密钥和会话密钥分离，历史会话不可恢复。
- U 盘被篡改：启动器至少校验 OpenSSH ZIP 的 manifest/SHA-256；正式发布仍必须增加发行包签名校验。
- 目标机无网络：切换为局域网直连，公网模式不可用。
- 局域网 UDP 发现只返回未认证的连接元数据；SSH 配对包只含公钥，不返回密码、令牌、私钥或状态路径。它可能被同网段主机伪造或监听，管理端应依赖目标机确认框和临时主机密钥，旧 WinRM 路径仍需人工确认后执行 `trust`。

## 当前实验版的确认行为与限制

- SSH/WinRM 向导已修复确认输入边界：仅成功读到完整空白行才允许系统修改，EOF、读取失败和不完整输入默认取消。
- GUI 正常结束 / TTL 清理会显示错误并保留恢复状态；没有独立 SSH revoke。专用手动服务宿主按窗口身份 / TTL 停止 SSH 子树，崩溃或重启后的账号、规则、服务注册和目录回收依赖下次确认恢复，完整系统路径尚未验收。
- 默认防火墙来源为 LocalSubnet；批准后的授权公钥使用 from= 限制来源 IP。运行目录 / 服务程序 / 主机密钥采用 SYSTEM 与管理员 ACL，StrictModes yes；UDP 首次信任和真实普通账号登录仍须验收。
- SSH 目标生命周期审计、审计失败处理和交互 shell 逐条命令审计不完整。
- 离线包仅校验 SHA-256，未实现签名/发布者信任；zip 与 manifest 同时被篡改时，摘要匹配不能证明来源可信。

只有用户明确同意且可回滚的可信 Windows 实验环境可以用于现阶段系统验收。不得因为历史手工连接成功而将这些缺口标记为解决。

临时 SSH 服务的注册及 SYSTEM 启动仅发生在配置确认后，StartupType 为 Manual，正常清理删除；它不是开机自启的业务 Agent。目标程序内部 `ssh-service` 仅在 SCM 回调、SYSTEM Session 0、精确归属目录及有效控制进程条件下启动 SSH。在线安装的系统 OpenSSH 功能不由本次清理卸载。
