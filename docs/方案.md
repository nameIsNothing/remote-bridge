# Remote Bridge 产品与技术方案

## 1. 背景

当前排查远程电脑时，需要在目标机本地手工执行 WinRM、TrustedHosts 和防火墙配置。Remote Bridge 将这些步骤封装成一次性启动程序，让 Codex 继续在管理电脑上工作。局域网实验模式还可在目标窗口存活期间通过 UDP 发现目标地址，减少抄写 IP 的步骤。

目标机不运行业务 Agent。它只运行一个受控的连接桥，提供临时 Shell 入口；排查结束后可以停止并回滚。当前局域网实验默认使用 SSH 公钥配对（TCP 2222），旧 WinRM 流程保留为兼容入口。

本方案包含未来路线，不等于各组件已实现。当前工程与缺口以 `开发交接.md` 为准；GitLab 服务器部署和运维属于同级 `gitlab-ops`，不混入本项目。

## 2. 目标与非目标

### 目标

1. Windows 目标机一键初始化并支持 PowerShell 远程命令。
2. 同一局域网内不依赖公网服务。
3. 跨互联网时由目标机主动连接 Relay，适配 NAT 和无公网入站端口。
4. 后续支持 Ubuntu/macOS，通过 SSH 提供 Bash/Zsh 命令行。
5. 所有设备注册、授权、命令和撤销都可审计。

### 非目标

- 第一阶段不实现远程桌面。
- 不绕过管理员授权、UAC 或系统安全提示。
- 不把管理员密码写入启动程序。
- 不支持目标电脑完全断网时的跨互联网连接。

## 3. 总体架构

```text
局域网模式：
Codex 管理机 ── WinRM/SSH ──> 目标机 Bridge

互联网模式：
目标机 Bridge ── HTTPS/WSS 出站 ──> Relay <── HTTPS/WSS ── Codex 管理机
                                        │
                              本地端口映射/SSH/WinRM
```

当前程序入口为 `bridge-target` 和 `bridge-cli`。下列组件是架构划分，其中 Relay、反向隧道和 Web 尚未实现：

- `bridge-bootstrap`：目标机一次性初始化器，负责检测系统、配置服务、生成密钥和输出连接信息。
- `bridge-client`：短期运行的连接桥；局域网模式可不需要常驻，Relay 模式负责保持出站隧道。
- `bridge-relay`：公网中继，负责设备注册、会话配对和字节转发，不默认保存终端内容。
- `bridge-cli`：管理端命令行，给 Codex 使用，负责设备授权、本地端口映射和撤销。
- Web 控制台：后续阶段，用于设备列表、授权、日志和会话管理。

## 4. 连接流程

### 局域网流程

1. 对方以管理员权限运行 Windows 启动器。
2. 启动器检查/安装 OpenSSH，创建固定用户名和随机初始化密码的临时账号；管理端不使用该密码，而是通过一次性 Ed25519 公钥配对。
3. 当前 SSH 实验入口的 TCP/UDP 规则使用 `LocalSubnet`；WinRM 脚本支持指定管理机地址，SSH 严格来源约束尚待实现。
4. 交互式窗口在有效期内响应管理端的 UDP 发现请求；公告只有地址、端口、账号名和过期时间，不广播密码或状态文件。
5. 管理端确认发现结果后发送公钥请求；目标机用户点击标准 Windows 确认框后建立 SSH PowerShell 会话。
6. SSH 正常回车退出或进程内 TTL 到期会调用资源清理；WinRM 使用显式 revoke。SSH 独立撤销、清理失败恢复和异常关窗处理尚待完善，不能把正常路径等同完整生命周期保证。

### 互联网流程

1. 对方运行启动器并确认授权。
2. 启动器生成设备密钥，使用一次性注册码连接 Relay。
3. 管理端输入注册码并批准设备。
4. Relay 建立目标机到管理端的临时数据通道。
5. `bridge-cli` 在管理机监听本地端口，Codex 连接该端口。
6. 会话超时、手工断开或撤销后，隧道立即关闭。

## 5. 技术选型建议

- Agent/启动器：Go，便于交叉编译为 Windows、Linux、macOS 单文件。
- 局域网 Windows：当前默认 OpenSSH 公钥配对，WinRM 保留兼容；继续完善统一连接运行时抽象和撤销流程。
- Linux/macOS：系统 SSH，启动器只负责密钥和防火墙检查。
- Relay 通道：TLS 1.3 上的 WebSocket 或 HTTP/2；第一版只做 TCP 字节转发。
- 管理端：Go CLI；Web 控制台放到第二阶段。
- Relay 部署：一台公网 VPS 起步，前置 Caddy/Nginx 提供 TLS。
- 状态存储：SQLite 起步，设备和审计记录不保存终端原文。

## 6. 关键接口

- `POST /v1/devices/register`：设备注册。
- `POST /v1/pairings`：创建一次性配对码。
- `POST /v1/sessions`：批准会话。
- `GET /v1/devices`：设备状态。
- `POST /v1/devices/{id}/revoke`：撤销设备。
- `GET /v1/audit-events`：查询审计事件。
- `GET /v1/tunnel`：设备和管理端建立 WebSocket 隧道。

## 7. 运行边界

目标机必须至少能访问管理机（局域网模式）或 Relay 的 HTTPS 端口（互联网模式）。目标机完全没有网络出口时，不能通过 Web 或公网 Relay 远程访问。
