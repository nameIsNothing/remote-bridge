# 管理端托管会话

当前发布包为 0.2.9-test.1，两端一起更新。目标用户确认建立入口后，管理机输入一次 Windows 账号密码；管理进程持有同一个已认证 PSSession，Codex 通过本地 CLI 或 MCP 使用该连接。WinRM 入口默认与上限均为 3 小时，从目标配置时起计算；管理端使用目标公布的同一绝对期限，重连不续期。升级需重新打开两端，已有连接不会自动延长。SSH 仍为 30 分钟。完整生命周期仍需真实双机验收。

## 用户流程

1. 目标机双击 bridge-target.exe，核对账号，确认配置，允许必要的标准 UAC，保持窗口打开。
2. 管理机双击 bridge-cli.exe，或运行 `.\bridge-cli.exe manage --discover --target <目标IP>`。只有一个目标时自动选择；多个目标时提示明确指定。HTTP WinRM 所需的精确 TrustedHosts 由程序准备，必要时请求标准 UAC。
3. 在原生密码窗口中输入公告账号的 Windows 密码。使用账号密码，不是 Hello PIN。
4. 登录后管理窗口显示电脑、账号、剩余时间及会话编号。点击“复制 Codex 交接指令”，粘贴到当前 Codex 对话。窗口保持打开。
5. Codex 先核对状态，再根据用户任务运行命令。管理端窗口、Codex 或目标端都可以结束连接。重新连接需要重新输入密码。

交接指令只包含会话编号、目标、账号、期限及本地程序路径；不包含密码或接口令牌。仅建立连接不会自动发起新的 Codex 任务，也不替用户授权额外操作。

## CLI 和 MCP

未配置 MCP 时，当前对话可直接通过命令行使用：

```powershell
.\bridge-cli.exe session list
.\bridge-cli.exe session status --id rb-<编号>
.\bridge-cli.exe session exec --id rb-<编号> --command "hostname; whoami; Get-Date" --json
.\bridge-cli.exe session close --id rb-<编号>
```

`session exec` 的 JSON 保留远端退出码；远端非零时 CLI 返回 21，连接失败返回 20。默认命令超时 30 秒，可设置 1–120 秒。一次只执行一条命令，并发请求明确拒绝。每条命令启动独立 PowerShell 子进程；工作目录、变量和模块不会在两条命令之间保留，需要在一条命令内完成关联操作。不提供交互终端。

本程序提供 STDIO MCP：`bridge-cli.exe mcp`。工具为 `bridge_sessions`、`bridge_status`、`bridge_execute`、`bridge_end_session`。MCP 只使用已经由用户建立的托管会话，没有密码参数或自动登录工具。

Codex 的一次性配置示例（程序应放在固定本机目录，不使用随时拔出的 U 盘路径）：

```powershell
codex mcp add remote-bridge -- "D:\Tools\RemoteBridge\bridge-cli.exe" mcp
```

或在 Codex 的 MCP 设置中使用等效配置：

```toml
[mcp_servers.remote-bridge]
command = 'D:\Tools\RemoteBridge\bridge-cli.exe'
args = ["mcp"]
```

官方入口：[Codex MCP 配置](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。本轮没有改动用户的全局 Codex 配置。新增 MCP 可能需要新会话或重新加载工具；不能承诺当前对话即时出现工具。交接指令中的 CLI 路径可直接用于当前对话。

## 连接与凭据

- Go 管理进程启动 PowerShell 连接工作进程；密码只在工作进程的原生输入窗口中输入，用于一次 New-PSSession。认证后释放 SecureString，不落盘、不进入参数、日志、Go 进程或模型上下文。
- 管理端私有目录：`%LOCALAPPDATA%\RemoteBridge\managed-sessions`。目录仅允许当前 Windows 用户访问，拒绝重解析路径。会话记录保存本地临时能力令牌，不保存 Windows 密码；正常结束删除工作脚本和配置，关闭记录移除令牌与地址。进程异常退出可能留下失效文件，后续调用会核对进程接口和期限，不把记录存在当作在线。
- 本机接口仅监听 `127.0.0.1` 随机端口，使用临时 TLS 证书和固定证书摘要、独立的客户端/工作进程令牌。关闭代理和重定向，校验 Host、请求格式及大小。证书私钥仅在内存中；接口不对局域网开放。
- 同一管理机的同一目标实例只允许一个管理窗口；用系统文件锁防止重复认证和反馈覆盖。同一 Windows 用户的其他本机程序属于相同信任边界，不能隔离已经拥有该用户权限的恶意进程。
- 远端身份、SID、实例和期限由同一 PSSession 核对，后续命令不再重新登录。普通账号只拥有它原来的远程权限，不自动增加管理员权限。

目标端配置窗口的 UAC 权限与远程命令令牌分开。既有 EDY 双机实测的 administrator=false，不能修改需要管理员权限的受保护系统配置。本版延长期限不会改变权限；没有修改 UAC 策略或自动授予管理员访问。

## 目标端生命周期

目标端在 Windows Known Folder 的 `ProgramData\RemoteBridge-WinRM\<实例>` 创建管理员控制的 lease.json，并预建单独的 feedback.json。目标账号只能读取入口元数据和写反馈文件，不能修改入口目录或 lease。v2 入口记录实例、账号/SID、主机、UTC 到期时间、窗口 PID、启动时间及存活状态更新时间，不保存密码。

目标窗口进程每秒原子更新一次受保护的入口文件；写入失败会报告错误并结束本次入口。认证后的远端脚本核对入口身份、active 状态、期限、注册信息和状态新鲜度（过去 5 秒内，最多容许向未来偏差 2 秒），再写入 connected 反馈；目标窗口才显示认证成功。PID 和启动时间作为注册记录保留，v2 不要求普通远程令牌查询管理员进程。0.2.8-test.1 在真实目标上因该查询无权限而返回空值；v1 入口仍可兼容，但遇到此情况明确提示更新目标端。

正常管理端退出写 disconnected，目标端回到等待。反馈不是通过未经认证的 UDP 包产生；同一目标账号本地进程仍属于信任边界。管理端突然断电时，显示状态可能滞后，不能以目标窗口旧的“成功”文字判断连接仍然在线。

目标端结束时先将入口标记为失效，再停止广播并回收本轮拥有的规则。目标程序被强制结束时，状态不再更新，最多 5 秒后拒绝继续执行；PID 被重用也不能刷新旧入口。存活更新不会延长入口到期时间。元数据保留为撤销记录，不宣称整个目录全部删除。

每次命令在启动前和运行中约每 200ms 检查入口及超时；目标端结束或到期会停止托管命令。命令进程先加入 kill-on-close Windows Job，随后才从标准输入接收命令，避免子进程在纳管之前执行；结束时回收该 Job 中的子树。输出每路保留最多 131072 个 UTF-16 字符，并显式标记截断。管理端退出会拒绝新命令并等待工作进程关闭；清理超时会报告未确认回收。

这不撤销账号原有的系统 WinRM 权限，也不回滚已经执行的命令，或保证撤回命令交给系统服务、任务计划等外部设施的工作。旧 `winrm/exec/shell` 兼容入口不具有本托管模式的入口校验。不能把“结束托管会话”称为禁用该账号所有远程访问。

## 审计与安全软件

逐条命令在派发前写入审计，记录会话、目标、账号、命令摘要/长度；完成后记录退出码和结果。审计失败时拒绝开始命令，完成审计失败时停止继续接受命令。输出和密码不进入审计日志。管理端审计位置仍为 `%LOCALAPPDATA%\RemoteBridge\audit.jsonl`。

本轮用户确认安全软件清除了测试脚本；已取消测试脚本中整段 Base64 包装，并将新增远端命令改为可读固定启动器和私有 stdin 传输。管理端仍使用临时可读 PowerShell 工作脚本，不能保证所有杀毒软件均不误报。若脚本被清除，报告入口失败并关闭会话；记录安全软件名称、检测名称和路径用于排查，不关闭防护、不自动恢复隔离文件、不添加排除项。保留 Windows 常规安全检查。

## 本轮验证与待验收

已加入回环 HTTPS/证书固定、能力令牌隔离、审计阻断、并发拒绝、到期、注册表式目录记录、CLI/MCP 协议和错误码测试；Windows 隔离测试模拟 PSSession，核对一次密码、一次连接、多条命令和连接回收。原生进程测试只使用临时入口文件和自身子进程，覆盖中文、非零退出码、输出截断、超时、撤销、到期、控制进程身份和子树回收。v2 回归测试仅对自身创建的子进程限制查询权限，复现旧空值错误，并验证新入口可用、陈旧/未来/撤销状态拒绝、进程结束后拒绝及状态写入失败反馈。具体本轮执行结果以开发交接记录为准。

test.3 的工作进程集成测试继续模拟密码、WinRM 认证和目标入口，但派发后使用真实 PowerShell Job 与生产命令执行体，核对整数超时参数、中文输出、远端退出码、CLI/MCP 及会话回收。该测试不再用假的 Receive-Job 结果掩盖参数绑定问题，也不建立真实 WinRM。

真实双机仍需核对：新包密码输入与窗口显示、错误密码、普通账号权限、目标端结束时正在运行的命令、管理端异常退出、期限、杀毒兼容性及清理审计。原用户 UAC 交接、首次普通账号授权与 SSH 独立 revoke 仍属于既有未完成项。
