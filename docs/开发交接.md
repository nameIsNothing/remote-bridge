## 2026-10-28 现场连接问题修复：多网卡发现与当前账号 WinRM 自动授权

用户通过 SSH 隧道用管理端连目标机 DESKTOP-AVEMMJD（WiFi 192.168.100.67，当前账号直连模式）时先后遇到两个问题，确认修复后要求提交推送并打包：一是管理端为多网卡机器（VMware/WSL 虚拟网卡），`bridge-cli` 默认向 255.255.255.255 发现时广播只从单一网卡发出、落不到真实网段，报“未发现正在等待连接的电脑”；二是连接时目标返回“拒绝访问”，根因是当前账号直连模式按设计不授予 WinRM 权限，而当前账号本身不在 Administrators/Remote Management Users，需手动授权才能连。两者均已在程序侧修复并各带测试。

## 当前连接参数与状态

- SSH TCP `2222`，UDP `37020`，固定普通临时账号 `RemoteBridge`；密码随机生成，不显示、不广播、不持久化。
- 防火墙 Profile Any、RemoteAddress LocalSubnet，保持公用 / 专用网络类别；公钥授权按来源 IP 绑定。现有系统 SSH 的端口 22 与全局配置不被替换。
- ProgramData 由 Windows Known Folder 获取，不信任环境变量重定向。状态 `ProgramData\RemoteBridge\ssh\active.json`，实例目录为其同级精确 ID 目录；拒绝重解析点与越界路径。
- 状态保存 ID、账号、端口、服务名、宿主 PID、目录和到期时间。服务名 `RemoteBridge-<ID>`，StartupType Manual，宿主复制到受保护实例目录，SYSTEM 启动前再次检查路径与控制进程身份。
- 不直接把 Session 0 服务放入 Session 1 窗口的 Job。由服务宿主在同一 Session 0 内创建、约束 SSH 子进程；窗口退出或到期时停止 SSH 子树。0.2.5 已实测 Session 0 的专用宿主 / SSH 与普通账号登录；TTL 和全部资源回收仍须单独验收。
- 正常结束 / 到期会尝试完整回收；清理失败保留元数据。GUI 被强制终止或断电后，宿主只负责停止 SSH 子进程；账号、规则、Manual 服务注册、目录与状态残留依赖下一次用户确认后的恢复，不宣称已实现无人值守完整回收。
- 管理端缓存 `%LOCALAPPDATA%\RemoteBridge\ssh-sessions`，当前用户 SID 独占 DACL；不读取已有永久 SSH 密钥。过期空闲缓存下次调用清理，无后台守护进程。`--forget-session` 不撤销目标授权。
- 在线安装的系统 OpenSSH 功能不卸载；新建的本次服务正常清理删除。UAC 在用户配置确认之后执行，标准确认不会重复出现。
- 旧 WinRM `revoke/rollback` 不处理 SSH `active.json`；WinRM HTTP 5985 / HTTPS 5986 兼容规则继续按旧路径处理。已有 listener / 系统规则不归本计划。

## 开发与构建入口

构建机准备 Go 1.22 或更新版本后：

```powershell
go version
go test ./...
go vet ./...
.\scripts\build.ps1
```

默认输出 `dist\windows-amd64`，包含两个 exe、标准 UAC 启动器、SSH 指引及离线 OpenSSH 包。整体 ZIP 需显式加 `-Archive`，只收录发布文件。源文档整理不会自动更新已有发布目录，必须重新构建才能使用对应版本。

无参数窗口可用于已授权的只读界面检查；取消配置弹窗，不运行 `gui --configure`。实际创建账号、规则与服务，以及远程命令验收，需要用户明确批准的两台可回滚 Windows 测试机：

1. 记录 Windows 版本、接口、已有 OpenSSH/WinRM/规则和工具版本。
2. 新包打开只读界面，检查待配置 / 异常提示、Tab / Escape、取消配置；旧控制台 EOF / 读取失败保持默认取消。
3. 目标确认配置 → 管理端发现 → 拒绝和批准公钥配对。
4. 使用新版 `bridge-cli ssh --discover --command` 检查身份、主机与结果；确认普通账号、第二条命令免重复弹窗、真实认证后显示成功。
5. 验证点击结束 / 正常关窗、TTL、重复启动、端口占用、配对超时和失败；核对 SCM、宿主和子进程。
6. 验证目标进程、临时账号、TCP/UDP 规则及计划目录回收，原有系统资源保持不变；异常退出与清理失败单独记录，不能假定通过。
7. 核验审计记录和管理端临时密钥/known_hosts 的清理，明确现有审计缺口。
